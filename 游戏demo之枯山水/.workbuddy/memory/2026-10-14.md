## 《枯山水》网页 Demo —— 从零搭建完成

**技术选型**：纯 Canvas 2D + 原生 JS，零依赖零构建，双击 index.html 即可运行。
刻意不用 ES module（避免 file:// 的 CORS 问题），全部用 `window.KS` 命名空间挂在全局。

**文件结构**
- `index.html` / `css/style.css`（界面能藏就藏：右上角几个淡字 + 底部浮出物件栏 + 参数面板）
- `js/params.js`　全部可调参数 + 参数面板的滑块清单（用户要反复调参数，这里集中）
- `js/noise.js`　值噪声 / fbm / 可复现 rng
- `js/garden.js`　庭院多边形（方形/长条/不规则）+ 预计算 SDF 网格（距离 + 最近边切向）
- `js/field.js`　★流向场（流函数 ψ，核心）
- `js/ripple.js`　★纹路生成（流线积分，核心）
- `js/sand.js`　砂面逐像素质感（起伏 fbm + 浮雕 + 颗粒）
- `js/objects.js`　石头/苔藓/水钵/竹/松，本体烘成离屏 canvas，另存模糊剪影做影子
- `js/audio.js`　WebAudio 现场合成（无音频文件）
- `js/main.js`　场景、光影、交互、保存

**关键技术决策（重要，别走回头路）**
1. 纹路用**流函数 ψ** 构造，速度 = (∂ψ/∂y, −∂ψ/∂x)，五点中心差分求梯度。
   这样场天然无散，流线永不重叠、永不压成一条线。
   **第一版用「扣掉法向分量 + 归一化」是错的** —— 会在石头下游叠成一条退化直线。
2. 石头的绕行项 = 椭圆偶极子 ψ = −taper·η/ρ²，ρ 跟着石头朝向转 → 朝向决定绕行形状。
3. 尾流 = 在石头下游对坐标做「压缩变换」ξ' = ξ/λ（λ 从 1 平滑过渡到 1+wake）。
   这是光滑同胚，不会折叠，能线性拉长影响范围 → 长尾流。过渡中心取 ξ=0.8L、宽度 0.6L 才能保证单调。
4. 影响窗口用 smoothstep 的 taper 收成 0 → 远处扰动干净消失 → 尾流会自动**汇合**闭环。
5. 水钵 = 圆形偶极子（把直线挡在环带外）+ 环带内用 `ringAt` 的切向场单独积分出同心圆。
6. 归一化速度只改快慢不改方向，流线几何不变，可以放心用。

**调过的参数（当前默认，实测最好看）**
spacing 22 / reach 1.9 / soft 1.30 / wakeStretch 1.1 / basinReach 3.6 / jitter 1.2
（第一版 spacing 16 + reach 2.6 太密太散，像被抹开；间距要和石头大小同量级）

**性能实测（Node/V8）**：空院 3.3ms、10 石 6.1ms、10石+水钵+苔 8.1ms；草稿模式约一半。
砂面烘制约 78ms（限 240 万像素）；SDF 28ms。

**验证方式**：写了 Node 无头测试（自建 DOM/Canvas 桩跑通 9 个脚本 + 120 帧 + 全套交互），
以及自写 PNG 编码器把纹路渲染成图片肉眼验收。这两套脚本用完已删除（在 .tmp）。

**已知取舍**：影子方向偏移随光变，但纹路沟的高光偏移是烘焙的（光转过 0.22 rad 才重烘）；
竹/松是程序化绘制，不参与流向场，只投影子。

## ★★ 重大改版：整体重写为 Three.js（当前版本，上面的 Canvas 版作废）

用户反馈 Canvas 2D 版"这个很无聊啊，而且效果很差"→ 整体重写为真 3D（Three.js）。

**技术栈**
- 仍零依赖零构建，双击 `index.html` 即可跑；Three.js 用 `vendor/three.min.js`（UMD 全局 `THREE`），**不要引入 ES module**。
- 本地调试：`python -m http.server 8137`。
- 新文件结构：`js/params.js`（参数+面板清单）/ `noise.js` / `shaders.js`（全部 GLSL）/ `sand.js`（砂面）/ `objects.js`（物件网格）/ `scene.js`（渲染器/相机/光/院子/拾取）/ `audio.js` / `main.js`。旧的 garden.js/field.js/ripple.js 已删除。

**核心：纹路改为 GPU 逐像素求流函数 ψ**
- 数学不变（流函数→无散→流线不重叠；椭圆偶极子绕行；下游压缩做尾流；水钵环带同心圆），但整段搬进 GLSL，每帧全屏 pass，纹路实时跟随石头。
- 高度 = 沟的横截面 `c=cos(2π·fract(ψ/spacing))`；c>0 为沟 `-depth·c^grooveSharp`，c<0 为脊 `ridge·(-c)^ridgeSoft`。ψ 等值线即流线 → 天然光滑、绕行。
- ψ→高度渲到 `WebGLRenderTarget`；砂面 PlaneGeometry 用 `MeshStandardMaterial.onBeforeCompile` 位移 `transformed.y`，并用高度场差分重算法线。

**★ 踩过的坑（别重犯）**
1. **法线空间**：Three 片元里 `normal` 是【视图空间】。世界空间高度差算出的法线必须 `normal = normalize((viewMatrix*vec4(nw,0.0)).xyz)` 才能赋值，否则整片砂被当倾斜→发暗（曾整片 ~105 灰）。
2. **AO 基线从 1.0 起**：`1.0 + hh*uAoStrength`；曾用 `0.66+…` 把平地压到 66%→发灰。
3. **`undulationAmp` 默认 0**：它的 fbm 进法线会和沟法线打架→"黑划痕"。
4. **shadow acne**：砂被顶起 ~0.1 单位，`sun.shadow.bias=-0.0012`、`normalBias=0.14` 才不出黑划痕。
5. **grainAmp 要极克制**（默认 0.06），否则像沥青/雪花。

**当前默认外观（实测平衡）**
- 砂 `#efe9db`：depth 0.07 / grooveSharp 0.85 / ridge 0.034 / spacing 1.6 / wobble 0.20 / grainAmp 0.06。
- 地板压到近煤色 `0x121110`：太阳 3.0 + 曝光 1.32 会把不够暗的地板打亮成土黄，必须压很低庭院才"浮在幽暗里"。
- 石头反照率 ~0.36（偏冷深灰）；light ambient 0.34 / intensity 3.0 / shadowRadius 1.8；camera dist 1.6 / tilt 50；exposure 1.32。
- `light.shadowDark` 是死参数（r150 MeshStandardMaterial 无独立 shadow opacity，接不进 shader），已从 P 与 PARAM_SPEC 删除；影子浓度改由 ambient 反着控制。

## ★ 画风改版：低多边形粉彩（用户反馈"太丑了"）

用户看完 Three.js 版后说「太丑了，可以做成风格化的画风」。
诊断：丑不在参数，在**方向**——写实光照会把几何的简陋全部放大（噪声球石头、圆锥当松、
圆柱当竹）+ 土气配色 + 纹路像斑马线。写了 4 个方案的 SVG 对比图让用户选，用户选**低多边形粉彩**。

**实现（三层手法，缺一层就不像）**
1. 新增 `js/facet.js`：`Facet.tint(geo, amp, seed)` 给每个三角面写围绕 1.0 的顶点色
   （low poly 的灵魂）；`Facet.outline()` 背面外扩描边。索引几何先 `toNonIndexed()`，
   否则共用顶点会被插值抹平色块。
2. 几何全部改粗：石头 `IcosahedronGeometry(1,1)`、水钵 9 棱、松/竹 6 棱，一律 `flatShading`。
3. 砂面纹路从「受光的沟」变成「一道暖褐色带」：`SAND_FRAG_TINT` 取代原 AO，
   `mix(diffuseColor, uRippleTint, k)`。法线强度降到 0.5、grain 关 0。
4. 光照：ambient 0.75↑ / intensity 1.6↓ / exposure 1.0，零高光 → 平涂感。
5. 配色（低饱和）：砂 `#f7eddd` / 纹路 `#e7d4b4` / 地板 `#c8c4d4` / 石 `#9a8fb4` /
   苔 `#a3bd8a` / 水 `#9dc3d6` / 描边 `#4c4655`。
6. 新增 `KS.P.style` 组（facetAmp / rippleTint / rippleMix / outline / sandSeg）；
   「色块反差」「纹路着色」做成实时滑块——只重写顶点色、不重建几何。
   砂面网格密度降到 `sandSeg=0.5`（面片大才像 low poly），但纹路是逐像素算的，依然清晰。

**★ 顺手抓到一个隐藏很久的 bug：手耙完全失效**
症状：draw call 有、三角形有，但 `rakeRT` 永远全 0。
根因：`PlaneGeometry(1,1).rotateX(-π/2)` 躺平后，三角形绕序相对「世界 XZ → 屏幕 XY」
的映射变成**顺时针**；Three 默认 `FrontSide` 会开背面剔除 → 笔刷在光栅化阶段被全数丢弃。
修复：`brushMat` 加 `side: THREE.DoubleSide`。**这个 bug 在改成粉彩风之前就存在**
（排查过程：读离屏纹理内容 + 拿恒定红片元做对照 + draw call 计数，三步定位）。

**验证**：无 JS 报错；面板 31 项 = PARAM_SPEC 31；色块滑块实时生效；手耙可见；
流动动画 wipe 0.483→0.983→1.0 完整收敛。预览图 `preview.png` / `preview_empty.png`。
