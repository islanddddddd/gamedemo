# 项目长期记忆 —— 游戏demo之枯山水

## 这是什么
一个叫《枯山水》的网页游戏：在白砂庭院里摆石头，砂纹是**算出来的**，会绕着石头走、在石头后面拖出尾流。

## 硬约束（用户明确划的线，改代码时必须守住）
1. **没有任何失败判定** —— 摆得乱不是失败，推平不是惩罚。
2. **没有分数、成就、进度条、解锁提示**。保存的庭院列表里不许出现"共完成 N 座"这类统计。
3. **纹路必须是算出来的，不是贴图画上去的** —— 这是游戏的灵魂。优先保纹路系统，其余都能简化。
4. **留白要舍得** —— 砂的面积远大于所有物件之和。
5. **不要加任何"目标"**。
6. 界面能藏就藏：平时画面上只有庭院。没有教程弹窗。
7. 声音克制、默认音量低，目标是"让人更安静"。

## 工程约定
- 技术栈：**Three.js（`vendor/three.min.js`，UMD 全局 `THREE`）+ 原生 JS**，**零依赖、零构建**，双击 `index.html` 就能跑。
  （旧版是纯 Canvas 2D，已因用户嫌"无聊、效果差"整体重写为真 3D —— 见当日日志。）
  因此**不要引入 ES module / import**（file:// 下会被 CORS 拦），自己的代码全部走 `window.KS` 全局命名空间。
- 全中文注释。**注释要解释"为什么"**，尤其是纹路生成的每一步——用户会反复调参数。
- 所有可调参数集中在 `js/params.js`，并且要在 `KS.PARAM_SPEC` 里登记，才能出现在游戏内的参数面板。
- 用户偏好：做工程/优化决策时，**先给可选方案再定方向**，不要直接替他决定。

## 核心算法要点（踩过的坑）
- 纹路用**流函数 ψ**（新版在 GLSL 里逐像素算，全套数学见 `js/shaders.js`）：
  高度 = 沟横截面 `cos(2π·fract(ψ/spacing))`，ψ 的等值线就是流线 → 天然光滑、绕行。
  ❌ 不要用"扣掉法向分量再归一化"——场有散度，流线会退化重叠。
  ✅ 用流函数 → 无散 → 流线永不重叠、尾流自动汇合。
- 尾流 = 下游坐标压缩变换（光滑同胚，参数要保证单调不折叠）。
- 水钵同心圆 = 环带外圆形偶极子挡开直线 + 环带内单独用切向场积分。
- ★ Three 着色器里 `normal` 是**视图空间**：世界空间算出的法线必须 `viewMatrix` 变换后再赋值，否则砂发暗。
- ★ 沟底 AO 要从 `1.0` 起算（平地不变暗）；`undulationAmp` 默认 0（其 fbm 进法线会和沟法线打架出黑划痕）。
- ★ **手耙笔刷必须 `side: THREE.DoubleSide`**：`PlaneGeometry(1,1).rotateX(-π/2)` 躺平后绕序相对
  「世界 XZ → 屏幕 XY」变成顺时针，FrontSide 的背面剔除会把笔刷全数丢光（症状：draw call 有、rakeRT 全 0）。

## 当前画风：低多边形粉彩（low poly pastel）
用户嫌 Three.js 初版"太丑"，四选一后定为低多边形粉彩。三层手法缺一层就不像：
1. **每三角面一个顶点色差**（`js/facet.js` 的 `Facet.tint`）—— low poly 的灵魂，粗几何也读得出体积。
   索引几何要先 `toNonIndexed()`，否则颜色被插值抹平。
2. **几何要粗 + flatShading**：石头 20 面体、水钵 9 棱、松/竹 6 棱；一律 roughness 1.0 / metalness 0（零高光）。
3. **纹路是色带不是阴影**：`SAND_FRAG_TINT` 把凹处 `mix` 向暖褐色，法线强度仅 0.5、grain 关 0。
配色集中在 `js/objects.js` 与 `KS.P.style`；光照 ambient 0.75↑ / intensity 1.6↓ / exposure 1.0。
砂面网格密度 `style.sandSeg`（默认 0.5，面片大才像 low poly），但纹路逐像素算，与网格密度无关。
**纹路系统（流函数 ψ）完全没动**——换画风不动灵魂。

## 用户的使用方式
- 会反复调参数找最好看的效果 → 参数面板和 `params.js` 的注释质量很关键。
- 沟通风格简短直接，喜欢先看到能跑的东西。
